# Devices dial out to the gateway, and only during a live session

`koreader_mcp` used to listen on port 8888 on every Kindle from KOReader start, opened its own firewall rule, polled its socket every 0.5 s and announced itself with `POST /register`. The gateway kept a list of addresses and an offline flag set by the first failed call, and only a new `/register` cleared it. That cost a Kindle an always-on timer and an agent server, and it stranded devices: a Kindle that woke with WiFi still up never registered again.

Now a device holds one outbound TCP connection to the gateway's `DEVICE_PORT` (default 9990), with newline-delimited JSON both ways: a hello naming the device, then tool calls and replies matched by id, and a ping every 60 s. A device is in `list_devices` exactly while that connection is open, so there is no address list and no offline flag to go stale. Either side treats 150 s of silence as a drop. On a Kindle the connection exists only during a session the owner starts in the menu; outside one the plugin has no socket and no timer. The emulator sets `live_mode = "always"`.

The gateway port must stay reachable from devices, and a dropped connection means a device is gone until it dials back, so a Kindle session reconnects after 5 s, 15 s and 60 s, then ends. A session also ends after 15 minutes without an agent command, or below 30% battery. A session survives a kill: `session_open` in the plugin's settings file brings it back at next start, otherwise every `restart_koreader` and `deploy_plugin` would lose the device for good, with the screen saver still held off.

Rejected: keeping the listener and adding a heartbeat. It fixes the stale flag but keeps a server and a timer running on every Kindle whether or not an agent is present. Rejected: refusing a name once it was ever bound to another device. The registry is in memory, so such a rule would not survive a gateway restart; a clash is refused only while the other device is connected.
