# The gateway serves MCP statelessly, with no session IDs

The gateway used to issue an `mcp-session-id` on `initialize` and keep each session in an in-memory map. Any time the gateway forgot a session (a container restart, or a closed stream deleting it from the map), the MCP proxy kept sending the old ID. The gateway answered with a fresh, uninitialized server, which returned `400 Server not initialized`, and a 400 never tells a client to start over. So every gateway tool failed through the proxy until the proxy was reconnected by hand. Now each `POST /mcp` gets a new server and transport with `sessionIdGenerator: undefined`. No session ID is ever issued, any ID a client sends is ignored, and `GET`/`DELETE /mcp` return 405. This is safe because the tools read only the shared device registry and keep no per-session state; adding per-session state later would mean reopening this decision. Rejected: answering an unknown session ID with 404 as the spec asks, so the client re-initializes. It works, but it relies on every client handling 404 correctly and still breaks once per gateway restart.
